## 2. Zero-shot matrix — COMPLETE (26 configs × 2 models)

26 configs mirroring every existing med42 run: 2 no-RAG + 24 RAG (2 indexes × dense/hybrid × coarse k20/off × reranker on/off × reformulation on/off), all 1,273 questions. Executed via `run_base_llama3.sh` (generated by `scripts_reviewer/generate_base_llama3_runs.py`, skip-guarded on `total==1273` metrics).

**Headline (McNemar exact test per config, bootstrap 95% CI):** med42 wins all 28 paired configs, mean gap **+19.2 pts**, all p < 0.001. Full table: `evaluation_results/base_vs_med42.csv`.

**Three findings:**

1. **Fine-tuning gap is +20–24 pts in zero-shot RAG and no pipeline component recovers it.** Base llama3 stays in a flat 30.8–38.8% band across every retrieval variant (bge/MedEmbed × dense/hybrid × all ablations); med42 is pinned at 55–60%.
2. **Base llama3 is hurt by retrieval; med42 is stabilized by it.** All 23 zero-shot RAG configs score *below* base's own no-RAG baseline (41.6%) — evidence distraction. Med42 never drops below 55%.
3. **Embedding-agnostic.** The 9 cross-embedding-consistent configs (dense 2³ ablation + 1 hybrid) replicate on both bge-large and MedEmbed with ≤2 pt within-config differences vs a ~22 pt model gap.

## 3. Supervisor verification: "no CoT used in retrieval" — VERIFIED

Code-level inspection (`src/rag_evaluation/evaluation.py`):

- Pipeline is single-pass: build queries → retrieve → build prompt → answer. No feedback loop; CoT output never re-enters retrieval.
- `use_cot` touches only the answer stage: prompt template (L517) and `num_predict` (L392: 512 CoT vs 2 direct).
- Retrieval queries = raw question (+ optional single-shot LLM rewrite: `max_tokens=120, temperature=0.0`, no reasoning; HyDE prompt explicitly says "No step-by-step reasoning" — HyDE off in all runs).
- **Nuance disclosed:** `reformulation_model` defaults to med42 regardless of `--llm-model` → retrieval (incl. reformulation) was *identical* across both models (no confound). The `no_reformulation` configs are the fully non-LLM-retrieval subset.

## 4. CoT + RAG — COMPLETE (minimal paired set)

Scope decision: full 9-config × 2-index × 2-model factorial rejected (~24–30 h) in favor of the **approved 3-run minimal set** (`run_cot_minimal.sh`), completed via `run_cot_minimal.sh` after the in-flight run from the grid was kept.

### Final paired CoT table (n=1273 per cell)

| Config | base llama3 | med42 | gap |
|---|---|---|---|
| NO_RAG / CoT | 51.7% | 59.7% | +8.0 |
| bge / dense / k20 / reranker_on / reform / CoT | 51.9% | 60.3% | +8.4 |
| bge / dense / k20 / reranker_off / no_reform / CoT | 51.7% | 59.5% | +7.8 |
| bge / dense / coarse_off / reranker_off / no_reform / CoT | 50.4% | 57.1% | +6.7 |
| medembed / dense / k20 / reranker_on / reform / CoT | 51.9% | 59.2% | +7.3 |

**Finding:** CoT lifts base llama3 **+14–16 pts** over zero-shot RAG (36→52%) but is **flat for med42** (±2 pts, ~59%). The fine-tuning gap shrinks from ~+22 to **+6.7…+8.4**, replicated on both embeddings. CoT also stops retrieval from *hurting* the base model (zero-shot RAG scored below its no-RAG baseline; CoT restores it to its no-RAG CoT ceiling, 51.7% = 51.7%).

Med42's only real CoT gain is without retrieval (no-RAG: 55.5 → 59.7, +4.2). One-liner for the paper: *chain-of-thought is a substitute for retrieval-induced context use in the base model, and redundant for the medically fine-tuned one.*

## 5. Token-cap audit

| Cap | Nominal | Actual | Impact |
|---|---|---|---|
| Evidence packing | 1,200 tokens | ~1.6k median, 99.4% of questions ≥1,150 (tiktoken-measured) | None — contexts byte-identical across models; matches original med42 setup |
| CoT answer | 512 tokens | base truncates 65/1273 (5.1%), 17 unparseable (1.3%); med42 24 & 2 | ≤1.3 pts on base CoT — bias is *conservative* (true gap slightly smaller) |

Disclosure text (paper-ready): *Retrieval packs ranked chunks under a nominal 1200-token evidence budget; delivered contexts average ≈1.6k tokens and are identical across models. Chain-of-thought answers are capped at 512 tokens, which truncates ≈5% of base-model generations (≤1.3 points of measured accuracy); the effect is negligible for the fine-tuned model. Truncation therefore biases our comparison conservatively.*
